# 인터뷰 질문 은행

단계별 질문과 선택지. **순서대로 다 묻지 않는다.** 이미 알게 된 것은 건너뛰고,
답에 따라 다음 질문을 바꾼다.

`AskUserQuestion`은 한 번에 최대 4문항이다. **묶음 단위로 묻는다.**
모든 문항에 `아직 모름` 성격의 선택지를 하나 둔다 — 모른다고 답할 수 있어야
빈칸을 지어내지 않는다.

---

## A. 정체 — 누구의 무엇인가

| 질문 | 선택지 |
| --- | --- |
| 이 프로젝트는 누구의 것인가? | 우리 회사 자체 / 클라이언트 수주 / 사내 특정 부서 / 개인 |
| 클라이언트·회사 이름 | (자유 입력) |
| 업종 | 제조 / 유통·커머스 / 의료 / 금융 / 교육 / 물류 / IT·SaaS / 전문서비스 / 기타 |
| 프로젝트 가칭 | (자유 입력) |

> 이름은 나중에 바뀌어도 된다. **지금 부를 이름**만 정하면 된다.

---

## B. 문제 — 왜 만드는가 (가장 중요)

이 단계를 대충 넘기면 나머지 전부가 흔들린다. 답이 얕으면 한 번 더 파고든다.

| 질문 | 선택지 |
| --- | --- |
| 지금 무엇이 문제인가? | (자유 입력 — 증상을 그대로) |
| 그 문제의 비용은 어디에 나타나는가? | 사람 시간 / 매출 기회 / 고객 이탈 / 오류·재작업 / 의사결정 지연 / 아직 모름 |
| 지금은 어떻게 처리하고 있는가? | 수작업 / 엑셀 / 외부 서비스 / 기존 시스템 / 아무것도 안 함 |
| 아무것도 안 만들면 어떻게 되는가? | 그대로 감당 가능 / 점점 악화 / 곧 못 버팀 / 기회를 놓침 |

**파고드는 방법** — "왜 그게 문제인가"를 두 번 더 묻는다.
증상(느린 응대) → 원인(문의가 흩어짐) → 근본(창구가 여러 개다).
근본에 닿아야 해법이 달라진다.

---

## C. 대상 — 누구를 위한 것인가

| 질문 | 선택지 |
| --- | --- |
| 실제로 쓰는 사람은? | 일반 소비자 / 기업 담당자 / 우리 직원 / 파트너사 / 여럿 |
| 돈을 내거나 도입을 결정하는 사람은? | 사용자와 같음 / 다름 (경영진·구매팀 등) / 무료 |
| 대략 몇 명이 쓰는가? | 10명 미만 / 수십 / 수백 / 수천 이상 / 아직 모름 |
| 기술 친숙도는? | 높음 / 보통 / 낮음 (안내가 많이 필요) / 섞여 있음 |

> 사용자와 결정자가 다르면 화면이 두 벌 필요할 수 있다. 반드시 확인한다.

---

## D. 성공 — 무엇이 되면 된 것인가

| 질문 | 선택지 |
| --- | --- |
| 출시 3개월 뒤 무엇이 달라져 있어야 하는가? | (자유 입력) |
| 그걸 어떻게 확인하는가? | 숫자로 측정 / 사용자 피드백 / 담당자 체감 / 아직 정할 수 없음 |
| 이번에 실패라고 부를 조건은? | (자유 입력) |

**측정 불가한 목표는 되묻는다.**
"사용자를 늘리고 싶다" → 몇 명에서 몇 명으로, 언제까지.
숫자를 모르면 "관찰 가능한 상태"로라도 바꾼다 — "문의가 한 곳에 모인다" 같은.

기준 데이터가 없으면 **목표 수치를 지어내지 않는다.** "출시 후 N주를 베이스라인으로"로 남긴다.

---

## E. 범위 — 무엇을 만드는가

| 질문 | 선택지 |
| --- | --- |
| 형태는? | 웹사이트 / 웹 애플리케이션 / 모바일 앱 / 사내 시스템 / AI 기능 / 아직 모름 |
| 없으면 출시 못 하는 것 3가지 | (자유 입력) |
| 있으면 좋지만 없어도 되는 것 | (자유 입력) |
| **이번에 하지 않을 것** | (자유 입력) |

반드시 **최종 목표 범위**와 **첫 출시 범위**를 따로 확인한다.

| 질문 | 선택지 |
| --- | --- |
| 최종적으로 어디까지 필요한가? | 전체 목표를 자유 입력 / 아직 모름 |
| 첫 공개에 반드시 필요한 것은? | 핵심 기능 3개 / 전체 동시 공개 / 아직 모름 |
| 구조만 준비하고 공개는 미룰 것은? | 콘텐츠·관리·자동화 후보 / 없음 / 아직 모름 |

사용자가 "전체"를 고르면 반대하지 말고, 콘텐츠·일정과 충돌하는지만 한 번 확인한다.

> **"하지 않을 것"이 비어 있으면 기획안이 아니다.** 반드시 받아낸다.
> 답을 못 하면 후보를 제시한다: 로그인 / 결제 / 다국어 / 관리자 화면 / 모바일 앱 / 알림.

## E-2. 규모 — 이 프로젝트는 얼마만 한가

**반드시 묻는다.** 이 답이 2단계의 문서 개수를 결정한다.
안 물으면 2주짜리 랜딩과 7개월짜리 커머스가 똑같은 문서 세트를 받는다.

| 질문 | 선택지 |
| --- | --- |
| 만드는 데 얼마나 걸릴 것 같은가 / 몇 명이 붙는가 | `solo` 혼자, 몇 주 / `small` 1~2명, 1~2개월 / `standard` 팀, 3~6개월 / `large` 다인원, 6개월 이상 |
| 돈이나 민감정보를 다루는가 | `low` 정보 제공만 / `standard` 로그인·개인정보 / `regulated` 결제·금융·의료·법정 의무 |
| 이번에 어디까지 내보내는가 | `prototype` 보여주기용 / `mvp` 최소 기능 출시 / `production` 실운영 |

**scale 은 사용자가 고른다.** 나머지 둘은 앞선 답에서 유도되면 그 값을 제시하고 확인만 받는다.

- E항에서 결제·주문이 범위에 있으면 `risk: regulated` 를 제시한다
- E항이 "시안만" 이면 `delivery: prototype` 를 제시한다
- C항 사용자 수가 수천 이상이면 `scale` 을 한 단계 올려 제안한다

> **모르면 넓은 쪽으로 둔다.** `scale: large`, `risk: regulated`, `delivery: production` 이 기본값이다.
> 작게 잡아 문서를 잃는 것보다 크게 잡아 지우는 편이 낫다.

---

## E-3. 산출물 — 무엇을 납품하는가

**반드시 묻는다.** 이 답이 2단계의 **산출물 정의서 v1** 이 되고, 거기서 WBS 과업이 나온다.
안 물으면 "만들어 달라고 한 적 없는 문서"를 만들거나, 오픈 직전에 없는 문서를 급조한다.

먼저 표준 목록을 한 번에 보여주고 **골라내게** 한다. 하나씩 묻지 않는다.

| 질문 | 선택지 |
| --- | --- |
| 고객에게 **문서로** 납품해야 하는 것은? | 요구사항 정의서 / 화면 설계서 / 데이터 모델(ERD) / API 명세서 / 테스트 계획 / 사용자 가이드 / 운영 이관 문서 (복수 선택) |
| 그중 **고객이 직접 읽는** 것은? | (위에서 고른 것 중 복수 선택) |
| 위 목록에 없는데 요구받은 산출물이 있는가 | 자유 입력 / 없음 |
| 산출물 목록을 **승인하는 사람**은? | 이름·역할 / 아직 모름 |

그다음 **빼는 것**을 받아낸다.

| 질문 | 선택지 |
| --- | --- |
| **납품하지 않기로 한 문서**는? | (고르지 않은 항목을 제시해 확인) |

> **"고객이 직접 읽는가"를 반드시 나눈다.** 이 값이 ELI5 적용 범위를 정한다.
> 고객이 읽는 산출물은 2단계에서 본문 전체를 평문으로 쓰고, 내부 문서는 요약만 평문으로 쓴다.

> 사용자가 "다 필요하다"고 하면 반대하지 않되 **한 가지만 확인한다** —
> "이 중에 고객이 실제로 검수하는 문서는 몇 개인가요?"
> 보통 그 숫자가 진짜 필요한 산출물 수다.

모르는 항목은 **대신 정하지 않고** `TODO(client)` 로 남긴다.
2단계가 "물어본 적 없음"과 "물었지만 미정"을 구분해야 한다.

## F. 제약 — 조건은 무엇인가

| 질문 | 선택지 |
| --- | --- |
| 일정 | 마감 확정 / 대략 목표 / 없음 |
| 그 날짜인 이유는? | 계약·법적 기한 / 행사·영업 일정 / 내부 목표 / 특별한 이유 없음 |
| 초기 제작비 | 확정 / 상한만 있음 / 직접 제작 / 미정 / 말하기 어려움 |
| 월 고정 운영비 | 0원 우선 / 상한 있음 / 품질 우선 / 아직 모름 |
| 사용량 비용 | 허용 / 상한 필요 / 발생하지 않게 / 아직 모름 |
| 운영 시간 부담 | 직접 관리 가능 / 자동화 우선 / 최소화 우선 / 아직 모름 |
| 기존 시스템과 연동이 필요한가? | 필요 (ERP·CRM 등) / 불필요 / 아직 모름 |
| 기술 제약 | 사내 표준 스택 있음 / 특정 클라우드 지정 / 보안 요건 / 없음 |
| 법·규제 | 개인정보 취급 / 산업 규제(의료·금융) / 접근성 의무(공공) / 해당 없음 |

> "예산은 나중에"라고 하면 **범위 상한만이라도** 받는다. 범위는 예산에 종속된다.

## G. 보유 자산 — 이미 가진 것

없는 것이 곧 리스크다. 2번 스킬이 이걸 Blocker로 올린다.

| 질문 | 선택지 |
| --- | --- |
| 브랜드 자산 | 로고·가이드 있음 / 로고만 / 없음 |
| 콘텐츠(글·이미지) | 준비됨 / 일부 / 없음 |
| 도메인 | 보유 / 미보유 |
| 실제 사례·실적 데이터 | 공개 가능 / NDA로 익명만 / 없음 |
| 기존 사이트·시스템 | 있음 (이전 필요) / 있음 (별개) / 없음 |

| 질문 | 선택지 |

| 좋게 본 서비스 | (자유 입력) |

## J. 다음 단계 힌트 (2번 스킬 전달용)

인터뷰 중 자연스럽게 드러나면 기록하고, 안 드러나면 묻지 않는다.

| 항목 | 판단 근거 |
| --- | --- |
| 추천 프리셋 | E항 형태 답변 |
| 검색 노출 필요 여부 | 공개 사이트인가, 사내 시스템인가 |
| 국내/해외 대상 | C항 |
| 광고 집행 계획 | 마케팅 언급 여부 |
| 다국어 | C항, F항 |
| 개인정보 취급 | F항 |

`option_hints`는 일부만 쓰지 말고 아래 13개를 모두 기록한다:
`seo`, `naver`, `geo`, `analytics`, `tagmanager`, `adtracking`, `consent`,
`a11y`, `perfbudget`, `i18n`, `cms`, `contactform`, `darkmode`.
