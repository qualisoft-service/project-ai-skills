## 산출물 폼 문법 — 이대로 만드세요

실제로 고객에게 나간 산출물에서 뽑은 형태입니다. **"정돈된 표"의 구체적인 모양이
이것입니다.** 원본 마크다운 표를 그대로 옮기면 이 모양이 되지 않습니다.

### 1. 시트·쪽에 번호를 붙여 읽는 순서를 못박습니다

```
1. 구축범위      2. 마일스톤      3. 산출물
```

`Sheet1`, `표1` 같은 이름을 쓰지 마세요. **번호 + 내용을 말하는 이름**입니다.

### 2. 표는 B열부터. A열은 여백입니다

A열 폭을 2~3으로 좁혀 왼쪽 여백으로 씁니다. 1행도 비웁니다.
표가 종이 끝에 붙으면 급하게 만든 문서로 보입니다.

### 3. 제목 줄 오른쪽에 전제를 씁니다 — 빠뜨리지 마세요

```
B2: 구축범위    │  D2: 추후 세부 업무 협의를 통해 변경 및 추가될 수 있습니다
B2: 마일스톤    │  D2: 본 일정은 IA 확정 이전 기준이며, 상세 기획 협의에
                │      따라 일부 변경될 수 있습니다
```

**고객 송부물에는 이 한 줄이 반드시 필요합니다.** 없으면 그 표가 확정 약속으로
읽히고, 나중에 범위·일정 분쟁의 근거가 됩니다. 원본에 근거가 없으면
`상세 협의에 따라 변경될 수 있습니다` 를 기본으로 씁니다.

### 4. 계층은 병합으로, 가장 작은 단위가 한 행입니다

**이것이 가장 중요한 규칙입니다.** 같은 상위 값을 행마다 반복해 찍지 마세요.
첫 행에만 쓰고 아래로 병합합니다.

```
항목        번호  주요화면   구성          설명              기능
─────────────────────────────────────────────────────────────────────
공통         1   로그인    로그인 인증   ID/PW 기반 인증   ID·PW 입력 인증
             2      ↑          ↑              ↑           역할에 따라 포털 분기
             3      ↑          ↑              ↑           5회 오입력 시 잠금
             4      ↑      비밀번호 찾기  본인 확인        가입정보 입력·인증
관리자 포털   8   밀도·통계  지역(글로벌)  히트맵 조회      검색 필터 & 히트맵
             9      ↑          ↑              ↑           지역 밀도 상세보기
```

`↑` 는 병합을 뜻합니다. **기능 하나가 한 행**이고, 화면·구성·분류는 병합으로
묶입니다. 이러면 고객이 "이 화면에 기능이 몇 개인지" 를 눈으로 셉니다.

번호는 **전체 통번호**입니다. 분류마다 1부터 다시 시작하지 마세요.

### 5. 일정은 주 단위 간트로 그립니다

표에 시작일·종료일만 적으면 기간이 보이지 않습니다. **머리행을 두 줄로 만들고
칸을 색칠하세요.**

```
Level      Task              Memo      1 month    2 month    3 month
                                      1w 2w 3w 4w 1w 2w 3w 4w 1w 2w 3w 4w
──────────────────────────────────────────────────────────────────────────
분석·설계  요구사항 상세화   - IA 확정  ██ ██
           DB 모델링         - 테이블      ██ ██
UI/UX      와이어프레임      - 화면별         ██ ██ ██
```

- 윗줄은 `1 month` `2 month` … 를 **4칸씩 병합**
- 아랫줄은 `1w 2w 3w 4w` 반복
- 막대는 **셀 배경색 채움** (`#B7B7B7`). 칸에 글자를 넣지 않습니다
- 주 칸 폭은 3~4로 좁힙니다
- `Level` 은 병합(분석·설계 / UI·UX / Front-End / Back-End / 외부 연동 / 통합테스트·배포)
- `Memo` 는 `- ` 로 시작하는 한 줄 설명

### 6. 일정 위에 오픈 차수를 세웁니다

간트 머리행 **위쪽 행**에 `1차` `2차` `3차` 를 해당 주 위치에 놓습니다.
고객이 가장 먼저 찾는 것이 "언제 쓸 수 있나" 입니다.

### 7. 상단에 요약 블록

간트 위에 두 줄을 둡니다.

```
총 기간   5개월 (개발 4 + 안정화 1)
전략      1차 오픈 → 빠른 사용 시작 (목록·기본 기능)
          2차 오픈 → 고도화 (대시보드)
          3차      → 사용자 피드백 반영
          4차      → 외부 연동·고도화
          5차      → 안정화
```

원본에 차수 전략이 없으면 **지어내지 말고** 총 기간과 주요 마일스톤만 씁니다.

### 8. 한 시트에 하나의 표만

구축범위와 마일스톤을 한 시트에 넣지 마세요. 성격이 다르면 시트를 나눕니다.
