# 디자인 규칙

> **3단계 기록이다.** 2단계 디자인 시스템 문서와 충돌하는 항목이 있으면
> 7항에 차이를 드러내고, 어느 쪽을 따를지 정해진 뒤에 반영한다.

> **`status` 는 사람만 올린다.** `draft` → `review` → `approved`.
> 3단계 진행률이 이 값을 읽는다 — 승인 전에는 100% 가 되지 않는다.
> AI 가 임의로 `approved` 로 바꾸지 않는다.

| 항목 | 내용 |

| 항목 | 값 | 근거 |

> 화면을 직접 보지 못하고 유추한 값에는 반드시 `추정`을 붙인다.

## 2. 인상

한 문장으로. 그리고 **그 인상을 만드는 요소**를 셋 이내로 적는다.

**피해야 할 인상** — 반드시 채운다.

## 3. 토큰

> **값은 여기에 적지 않는다.** 정본은 `tokens.css` 하나이고, 실제 값과 명도비는
> `styleguide.html` 이 그 파일을 읽어 렌더한다.
> 값을 문서에도 적으면 두 곳이 되고, 두 곳은 반드시 갈라진다.
> 여기에는 **어떤 토큰이 있고 무엇에 쓰는지**만 적는다.

### 색

| 토큰 | 용도 | 주의 |
| --- | --- | --- |
| `--bg` | 기본 배경 | |
| `--ink` | 본문 | |
| | | 어두운 면에서 뒤집어야 하면 여기에 적는다 |

### 타이포그래피

| 토큰 · 항목 | 용도 |
| --- | --- |
| `--font-display` | 제목·메뉴·버튼 |
| `--font-body` | 본문 |
| `--text-display` `--text-h2` … | 크기 스케일 |
| 본문 하한 | 16px / 캡션 하한 (예외는 7항에) |

### 간격 · 형태

| 토큰 · 항목 | 용도 |
| --- | --- |
| `--container` | 콘텐츠 최대 폭 |
| `--section-y` | 섹션 상하 여백 |
| `--radius-*` | 면 · 카드 · 작은 UI |
| `--shadow-*` | **쓰기로 한 곳만 명시한다** |
| `--tap` | 최소 터치 영역 |

> 새 토큰을 만들면 이 표에 이름을 추가한다. 빠뜨리면 `build.mjs check` 가 경고한다.

## 4. 레이아웃 원칙

- 정렬, 열 구성, 리듬
- 반복과 변주를 어디서 쓰는가

## 5. 안티패턴

2단계 디자인 시스템의 금지 목록을 그대로 옮기고, 이번 규칙에서 추가된 것을 덧붙인다.
**시안이 이 목록을 어기면 안 된다.**

## 6. 기준 예외

매체 기준(글자 하한 · 터치 타깃 · 대비)을 **의도적으로 벗어난 곳**을 여기 적는다.
적지 않으면 나중에 누가 "버그네" 하고 되돌린다. 반대로 여기에 없는 위반은 버그다.

| 기준 | 원래 값 | 예외 값 | 적용 범위 | 이유 | 보상 조치 | 하한 |
| --- | --- | --- | --- | --- | --- | --- |
| | | | | | | 여기서 더 내리지 않는다 |

> **보상 조치를 반드시 적는다.** 글자를 줄였으면 대비를 쟀다든지,
> 터치 타깃을 줄였으면 어느 기준(WCAG 2.5.8 = 24px)은 지켰다든지.
> 예외에 하한이 없으면 그건 예외가 아니라 기준 폐기다.
