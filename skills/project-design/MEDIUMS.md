# 산출 매체별 규칙

시안은 **무엇으로 나가느냐**에 따라 만드는 법이 다르다.
같은 디자인 규칙이라도 웹과 슬라이드는 글자 크기 기준부터 다르다.

기본값은 2단계 `Docs/docs.config.json` 의 `preset` 에서 추정한다.
`web-corporate` → 웹, `mobile-app` → 모바일 앱, `internal-system` → 어드민.
추정이 맞는지 **사용자에게 확인은 받는다.**

---

## 웹 (반응형)

| 항목 | 기준 |
| --- | --- |
| 시안 형태 | `mockup-web.html` — 브라우저에서 그대로 확인 |
| 확인 폭 | 390 / 768 / 1280 / 1536 |
| 본문 최소 | 16px. 캡션도 13px 아래로 내리지 않는다 |
| 터치 타깃 | 모바일 폭에서 44×44px 이상 |
| 검수 | **`audit.html` 로 자동 판정.** 손으로 감사 스크립트를 짜지 않는다 |

`audit.html` 이 판정하는 것 — 가로 스크롤 · 뷰포트 이탈 · **합성 명도비** ·
터치 타깃(24px 필수 / 44px 권고) · 글자 하한 · 포커스 링 · **스크롤 상태 전환** · 죽은 CSS.

**명도비는 토큰 쌍이 아니라 합성 결과로 잰다.** 실제로 터지는 결함은
`검정 배경 위 검정 글자`(CSS 우선순위 사고), `opacity 를 먹은 회색 글자`,
`고정 글라스가 어두운 섹션 위를 지날 때`처럼 전부 합성에서 나온다.
스타일 가이드의 토큰 표로는 원리적으로 안 잡힌다.

## 모바일 앱

| 항목 | 기준 |
| --- | --- |
| 시안 형태 | `mockup-app.html` — 디바이스 프레임 안에 렌더 |
| 기준 크기 | 390×844 (iOS 기준). Android는 폭 360 확인 |
| 세이프 에어리어 | 상단 노치·하단 홈 인디케이터 영역을 침범하지 않는다 |
| 터치 타깃 | **최소 44×44pt.** 웹보다 엄격하다 |
| 플랫폼 차이 | 상단 바·뒤로가기·기본 제스처가 iOS/Android에서 다르다. 어느 쪽 기준인지 규칙에 적는다 |
| 검수 | 한 손 조작 영역, 스크롤 시 고정 요소, 키보드가 올라왔을 때 |

> 앱은 **화면 전환**이 디자인의 절반이다. 정적 화면만 그리지 말고
> 어디서 어디로 가는지를 `design-rules.md` 에 적는다.

## 데스크톱 앱 · 어드민

| 항목 | 기준 |
| --- | --- |
| 시안 형태 | `mockup-web.html` (밀도만 높임) |
| 정보 밀도 | 여백을 줄이고 한 화면에 더 담는다. 마케팅 사이트 기준을 그대로 쓰지 않는다 |
| 핵심 패턴 | 표, 필터, 폼, 일괄 작업, 빈 상태, 오류 상태 |
| 검수 | 행이 수백 개일 때, 열이 넘칠 때, 값이 아주 길 때 |

## 발표자료 (PPT · 키노트)

| 항목 | 기준 |
| --- | --- |
| 시안 형태 | `mockup-slides.html` — 16:9 슬라이드 |
| 크기 | 1920×1080 기준으로 그리고 축소 표시 |
| 글자 최소 | **제목 40px, 본문 24px 이상.** 뒷자리에서 읽혀야 한다 |
| 한 장 = 한 메시지 | 슬라이드에 두 주장이 들어가면 나눈다 |
| 검수 | 축소했을 때 읽히는가, 흑백 인쇄에서 구분되는가 |

> 발표자료는 **말이 주고 슬라이드가 보조**다. 슬라이드에 문장을 다 넣지 않는다.

## 대시보드 · 데이터 리포트

차트가 들어가면 **`dataviz` 스킬을 먼저 로드한다.**
차트 코드를 한 줄이라도 쓰기 전에 로드하는 것이 그 스킬의 사용 조건이다.

| 항목 | 기준 |
| --- | --- |
| 시안 형태 | `mockup-web.html` + 차트 |
| 색 | 계열색·발산색 규칙은 `dataviz` 를 따른다. 임의로 정하지 않는다 |
| 검수 | 색각 이상에서 구분되는가, 축·범례가 잘리지 않는가 |

## 다이어그램 · 구조도

구조도·플로우가 주 산출물이면 **`artifact-diagramming` 스킬을 로드한다.**
인라인 SVG 작성법과 명암 테마 대응이 거기에 있다.

## 외부 공유용 문서 · 리포트

시안이 아니라 **읽히는 문서**가 목적이면 **`artifact-design` 스킬을 로드**하고
Artifact로 퍼블리시하는 편이 낫다. `_design/mockups/` 에 두는 것은
프로젝트 내부에서 확인할 시안일 때다.

## 인쇄물 (명함 · 브로슈어)

| 항목 | 기준 |
| --- | --- |
| 시안 형태 | `mockup-web.html` 을 mm 기준으로 (`@page` + `mm` 단위) |
| 재단 여백 | 사방 3mm 여유. 잘려도 되는 영역과 안 되는 영역을 표시 |
| 색 | 화면 RGB와 인쇄 CMYK는 다르게 나온다. **화면 색을 그대로 약속하지 않는다** |
| 글자 최소 | 6pt 아래로 내리지 않는다 |

## 매체를 모를 때

물어본다. 추정하지 않는다. 다만 선택지는 좁혀서 제시한다 —
2단계 프리셋과 화면 정의서를 보면 대개 하나로 좁혀진다.

여러 매체가 동시에 필요하면 (예: 웹 + 발표자료) **매체마다 시안을 따로 만들고
규칙은 하나로 공유한다.** 토큰이 갈라지면 브랜드가 갈라진다.
