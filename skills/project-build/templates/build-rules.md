# 구현 규칙

> **4단계 기록이다.** 스택과 폴더 구조의 정본은 기술 아키텍처 문서다.
> 여기에는 **그 문서가 정하지 않은 것**과 **구현하며 새로 정한 것**만 적는다.

> **`status` 는 사람만 올린다.** `draft` → `review` → `approved`.
> 4단계 진행률이 이 값을 읽는다. AI 가 임의로 `approved` 로 바꾸지 않는다.

## 1. 스택 확인

기술 아키텍처 문서에서 읽은 값을 그대로 옮긴다. **여기서 정하지 않는다.**

| 영역 | 값 | 출처 |
| --- | --- | --- |
| | | `*-tech-architecture` N항 |

**문서에 없는데 추가한 의존성** — 없으면 "없음"이라고 적는다.

| 패키지 | 왜 필요했나 | 대안을 검토했나 |
| --- | --- | --- |

## 2. 토큰 연결

`Docs/_design/tokens.css` 가 정본이다. **값을 복사하지 않고 링크한다.**

```css
/* src/styles/theme.css */
@import "tailwindcss";
@import "../../Docs/_design/tokens.css";

@theme inline {
  --color-ink: var(--ink);
  /* … 이름만 잇는다 */
}
```

값을 옮겨 적으면 두 곳이 되고, 두 곳은 반드시 갈라진다.
`build.mjs check` 가 복사를 감지해 경고한다.

## 3. 시안 대조 표식

시안과 구현 양쪽에 `data-parity="이름"` 을 단다. 클래스 이름은 달라도 된다.

| 표식 | 시안 | 구현 |
| --- | --- | --- |
| `header` | `.site-header` | |

**시안에 없는 화면**은 표식 짝이 없다. 그건 정상이므로 여기에 "시안 없음"으로 적는다 —
적지 않으면 빠뜨린 것과 구분되지 않는다.

## 4. 문서가 미결로 남긴 것

**대신 결정하지 않는다.** 물어보고, 답이 없으면 비워 두고 리스크에 올린다.

| 항목 | 출처 | 상태 |
| --- | --- | --- |

기술 아키텍처가 다루지 않은 판단이다. 이유를 함께 적는다.
